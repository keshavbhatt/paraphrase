Notes

  1. The run button sits at the bottom right of the left pane, below what it works on, and is named after what it does: the selected action and preset ("Proofread", "Casual", "Into Hindi", "Bullets"), "Write 3 replies" or "Write the reply" for Reply, "Write it" for Write. Its icon is the action's, as in the menus and History. It shows Ctrl Enter as a chip, the way Copy shows its keys, so the shortcut is learned by seeing it. It keeps one width whatever the label; a label that would not fit is cut with "…" and shown whole in its tooltip.
  2. The hint no longer carries the shortcut: "Type or paste anything, then run the action." Messages that named Ctrl+Enter say "Run it again" instead.
  3. Primary or not: the run button is the main (filled) button while there is no result for the text on screen: before the first run, and again once the text or an option has changed after a run. When a result for it is showing, it steps back to a plain button and Copy is the only filled one. Only the fill changes, never the size or place.
  4. Reply and Write wait for you: choosing them opens their form with the cursor in the first field and runs nothing while that field is empty. Choosing them with the form filled runs at once, as now. Every other action still runs as soon as it is clicked; the button is for running again and for the forms.
  5. Nothing to run: while the field it needs is empty, the button is shown but disabled, and the hint says what is missing ("Paste the message you got first", "Say what to write first", "Type or paste some text first"). It enables as soon as there is text.
  6. While a run goes the button is disabled at the same width; Stop stays where it is on the right (main-window-busy.html).
  7. Header buttons (proposed 2026-10-27): History and Settings have 10px padding and sit 4px apart, so "On this device", History and Settings are evenly spaced (about 24px between words) when no button shows its background; the open or hovered one still shows its full background.
