Use Paraphrase over any app

Select text anywhere, press the shortcut, pick an action, and the result goes back where the text was. Your desktop asks you about each of these once. You can skip both: everything also works in Paraphrase's own window.

Put the result back

Your desktop asks in its own window
Paraphrase types only after you press Replace or Insert, into the window the text came from, and never sends a message. Nothing you write leaves this computer.

Notes

  1. The shortcut: set through the desktop when it offers one (the KDE and GNOME shortcut portal), its own dialog lets the user change the keys. Where it cannot be set, the row says how to bind paraphrase-app --popup by hand (settings-general-shortcut.html), with no button.
  2. Shortcut states (approved 2026-10-27): (a) Change keys and (b) Choose keys open the desktop's own shortcut window (the portal's ConfigureShortcuts, version 2), and the row updates when the keys change. (b) replaces "By hand" when the desktop offers app shortcuts but this one has no keys, which happens when the keys are taken. On a portal without that window, (a) has no button and (b) asks the desktop for the shortcut again. The row follows the desktop live: it never keeps a status read at startup.
  3. Put the result back: Allow opens the desktop's own "Control input devices" dialog now, at setup, instead of at the first Replace after a wait (owner, 2026-10-23). The answer is remembered, so it is asked once; a "no" leaves Replace on the clipboard with "press Ctrl+V". On X11 there is nothing to ask (d).
  4. Optional: Skip for now and Next both go on; nothing here blocks setup (ADR-013: standalone first). The same two rows are in Settings, General and shortcut. This step comes first in setup again: the placeholder "Shortcut (later)" step goes.
