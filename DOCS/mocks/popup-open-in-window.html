Notes

  1. Open in window on every result: the expand button the actions page already has (popup-actions.html) is now in the header of every result page too, at the same place. It hands over the text, the action and its options, and the popup closes. The window comes up in front (the popup's activation token).
  2. A long message stays a few lines tall and scrolls inside its box, so the replies and the buttons stay on screen (built 2026-10-26).
  3. Need more than a line? Quick replies are one-liners; an email usually needs a full reply. This row, under the three replies, says so where the user is looking and opens the window on a full reply. It shows on every quick reply, short message or long.
  4. Reply opens on Full reply with the message in its field (from the reply row or the expand button). The cursor is in "What do you want to say?", which stays empty; nothing runs until the user presses Write the reply (Ctrl+Enter), so the model never starts on its own. Write it as follows the message: Email for a mail with a greeting or several paragraphs, Chat message otherwise; the user's last choice wins when it was made in the window.
  5. Other actions (Proofread, Tone, Summarize, Format, Translate, My actions) open on that action with the text on the left and, when the popup had a result, the same result on the right with its Copy, without running again. Opened while it still runs: the popup's run stops and the window waits for Run, with the same text and options.
  6. Nothing extra is kept: the hand-over is in memory. History records the run once, where it finished (opt-in history only).
